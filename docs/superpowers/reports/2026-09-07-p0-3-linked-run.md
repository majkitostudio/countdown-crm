# P0.3 — skutečný linked důkaz

**Datum:** 7. 9. 2026

**Stav:** úspěšně ověřeno

## Co bylo spuštěno

Runner byl spuštěn proti linked sandboxu `countdown-crm-sandbox-20260824`.
Finální běh po code review použil krátkodobý scoped Supabase Personal Access
Token omezený na tento projekt a přesně dvě čtecí oprávnění: `Database: Read`
a `Data API Config: Read`. Hodnota tokenu ani celý project ref nejsou v tomto
reportu uvedené.

Příkaz:

```text
npm run verify:linked-security
```

Runner použil read-only databázový Management API endpoint a autoritativní
PostgREST config endpoint. Databázový dotaz pároval všech pět RPC podle schématu,
jména a úplných identity arguments. Seznam Data API schémat pocházel z pole
`db_schema` skutečné PostgREST konfigurace, nikoli z nastavení SQL session.
Nebyl použit existující CLI session, `SUPABASE_SECRET_KEY` ani
`SUPABASE_SERVICE_ROLE_KEY`.

Původní pre-review běh s oprávněním pouze `Database: Read` nebyl autoritativní
pro kontrolu Data API exposure a je tímto finálním během nahrazen.

## Co tento report dokazuje

- vzdálený linked sandbox byl skutečně dotázán přes runner,
- všech 8 definovaných P0.2 databázových kontraktů bylo pravdivých,
- runner použil oddělený token s pouze dvěma potřebnými read-only oprávněními,
- kontrola RPC odlišuje správné signatury od overloadů se stejným názvem,
- kontrola `private_schema_not_exposed` pochází ze skutečné PostgREST konfigurace,
- runner neprováděl SQL zápis, migraci, pgTAP write test ani reset databáze,
- výstup neobsahuje token, heslo, connection string ani raw databázová data.

databázi a nenahrazuje lokální pgTAP testy. Produkční databáze nebyla použita.
